Quick start

                

                  Free Claude Code is a local proxy that speaks Anthropic's
                  API. Your coding agent thinks it is talking to Anthropic; this
                  proxy forwards the request to whichever provider you configure and
                  translates the response back. Streaming, tool use, reasoning and image
                  input keep working.
                

                
    
                  
  1. Add a provider key under Providers and press
                    Validate, then Apply.
    2. 
                  
  2. Map the model tiers under Model Config.
    3. 
                  
  3. Point your agent at this server — run fcc-claude,
                    or set ANTHROPIC_BASE_URL yourself.
    4. 
                

                

                  The proxy has to stay running for your agent to work. It is a server,
                  not a library. This dashboard is restricted to loopback callers, but the
                  proxy API itself binds to all interfaces by default — set
                  HOST=127.0.0.1 to keep it local, and change
                  ANTHROPIC_AUTH_TOKEN from the default if anything else can
                  reach the machine.
                


                
API keys

                

                  Each provider card on the Providers tab takes a key.
                  Validate makes a real call, so a green result means the key works
                  and the model you selected is reachable with it.
                

                
    
                  
  • 401 — the key is wrong.
    • 
                  
  • 404 — the key is usually fine, but the
                    model id is not available on your account.
    • 
                

                

                  Everything here is stored in ~/.fcc/.env. You can edit that
                  file directly instead; restart the server afterwards, since config is read
                  at startup.
                


                
Models

                

                  Routing is by tier, not by a single model: Fable, Opus,
                  Sonnet, Haiku and a fallback each map to a real model on your provider.
                  When your agent asks for Sonnet it gets whatever you mapped Sonnet to
                  — which is why its own model picker lists this catalog.
                

                

                  Map Haiku to something cheap and fast. Agents use the
                  small tier constantly for internal bookkeeping, and a slow model there
                  makes the whole session feel sluggish even when your main model is quick.
                


                
Connect a client

                

                  Claude Code (CLI). Configure it through its settings
                  file, not shell variables — ~/.claude/settings.json
                  (%USERPROFILE%\.claude\settings.json on Windows) wins over
                  exported environment variables. Merge these two entries into any
                  env block you already have:
                

                
{
  "env": {
    "ANTHROPIC_AUTH_TOKEN": "freecc",
    "ANTHROPIC_BASE_URL": "http://127.0.0.1:8082"
  }
}

                

                  The token authenticates your agent to this proxy and must match the
                  server's ANTHROPIC_AUTH_TOKEN (shipped as
                  freecc). It is not a provider key. Restart Claude Code and
                  check /status — it should report the base URL above.
                  Prefer not to edit files? Run fcc-claude instead.
                

                

                  Claude Desktop has a native gateway setting. Open
                  Help → Troubleshooting → Enable Developer Mode, then
                  Developer → Configure Third-Party Inference… and set
                  Connection to Gateway, base URL to
                  http://127.0.0.1:8082, API key to freecc, auth
                  scheme to bearer, credential kind to
                  Static API key, and Model discovery on. Use
                  Test connection before restarting — the server has to be
                  running. With a gateway active the app runs local sessions only.
                

                
Codex and Pi have their own launchers:

                
fcc-codex
fcc-pi


                
Web search

                

                  Claude Code's web_search is normally executed and billed by
                  Anthropic. This proxy fulfils it locally against a provider you pick, so
                  no Anthropic search credits are used and it works with any model provider.
                

                

                  WEB_SEARCH_PROVIDER=auto works with zero
                  configuration — with no keys set it falls back to keyless
                  DuckDuckGo. Set a key for anything else and auto prefers it.
                  A missing key always fails visibly rather than silently degrading.
                

                

                  The setting most worth changing: by default most
                  providers return a one or two sentence snippet. Several can return the
                  extracted text of the page, which is the difference between the model
                  guessing from a summary and actually reading the source.
                

                
EXA_CONTENTS=text
TAVILY_INCLUDE_RAW_CONTENT=markdown
FIRECRAWL_SCRAPE_FORMAT=markdown

WEBSEARCH_DIGEST_CONTENT_CHARS=4000

                

                  Extracted text has its own cap, separate from the snippet cap, so opting
                  in is not trimmed back to snippet length. It costs more on most providers
                  and adds input tokens to every search — each option's drawer states
                  its cost. Jina, Parallel and Linkup return extracted text by default.
                

                

                  Useful for coding work: FIRECRAWL_CATEGORIES=github,research
                  restricts results to GitHub or papers, and
                  TAVILY_CHUNKS_PER_SOURCE=3 is the cheapest way to get more
                  text out of Tavily.
                


                
Analytics

                

                  Two local SQLite stores under ~/.fcc/logs/, both written by a
                  background thread so they never block a request.
                  Analytics covers model requests; Web
                  Search has its own.
                

                
Input tokens are reported in two parts:

                
    
                  
  • Input (uncached) — prompt tokens the provider
                    actually processed.
    • 
                  
  • Cached input — prompt tokens served from the
                    provider's cache.
    • 
                  
  • Cache hit rate — cached divided by total
                    input.
    • 
                

                

                  A hit rate of — means that provider never reported
                  caching at all, which is different from a measured 0.0%.
                  Prompt caching is provider-dependent: OpenAI (prefixes of 1,024+ tokens)
                  and DeepSeek report it. NVIDIA NIM's hosted endpoint does not do real
                  prefix caching, so a near-zero rate there is accurate rather than a fault.
                

                

                  Every row has a View dialog with the full exchange and the
                  resolved configuration — usually the fastest way to see what
                  actually happened. Web search analytics separate logical searches
                  from provider attempts, so a fallback shows as one search and
                  several attempts.
                

                

                  Search content routinely includes private queries and page text. Setting
                  WEBSEARCH_LOG_CAPTURE_CONTENT=false withholds the payloads
                  and the query text, keeping only lengths and hashes. API keys are
                  never written to either store — only masked labels.
                


                
Key rotation

                

                  Model and web search providers both accept several keys in one variable:
                

                
EXA_API_KEY="key-a,key-b,key-c"
EXA_API_KEY_ROTATION=failover

                

                  Policies are single, round_robin,
                  least_used and failover — the default is
                  failover with several keys, single with one.
                

                

                  Health is tracked per key: repeated failures cool a key down on a rising
                  ladder, sustained failures open a circuit, and auth failures lock it out
                  for longer each time. A rate-limited key is benched for exactly as long as
                  the provider asks via its Retry-After header, rather than an
                  invented fixed delay.
                


                
Updating

                

                  The version panel announces new releases with their notes inline.
                  Update now downloads the wheel, verifies the SHA-256 that GitHub
                  publishes for it, and installs it. A checksum mismatch aborts. Extras you
                  installed, such as voice support, are preserved.
                

                

                  Upgrading never restarts the server, so it cannot drop an in-flight
                  stream — you restart when it suits you.
                

                

                  On Windows the install is deferred. Windows holds the
                  running interpreter open, so the environment cannot be replaced underneath
                  a live process. The verified wheel is staged and a background helper
                  installs it once you stop the server. Your working install is untouched
                  until then, so a failed update cannot strand you.
                


                
Troubleshooting

                
    
                  
  • fcc-server not found after installing
                    — close and reopen your terminal. The installer extends
                    PATH; an already-open shell will not see it.
    • 
                  
  • Two configs on Windows — installing under both
                    PowerShell and WSL gives you separate .fcc directories. The
                    server prints which one it is using at startup.
    • 
                  
  • Validation fails with 404 — usually the model
                    id, not the key.
    • 
                  
  • Agent cannot reach the proxy — check the
                    address in the startup log. The proxy is loopback-only by design.
    • 
                  
  • Web search returns nothing useful — open the
                    attempt detail in Web Search analytics; it shows exactly what was sent
                    and returned.
    • 
                

                

                  The full written guide, with screenshots, lives at
                  docs/USAGE.md in the repository.
